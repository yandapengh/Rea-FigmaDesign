一次真實的查詢：哪些頁面是彈窗

從一句話，到一個可以貼回 Figma 的答案。中間每一次工具呼叫、每一組數字，都是實際跑出來的。

方法篇：數據脫水的核心方法 · 架構篇：背景與整體架構

1 · 任務

你
這份檔案裡，哪些頁面是彈窗？大概多少個？
agent

先確認一件事：「彈窗」是指版面上有遮罩層，還是設計師分類為 dialog？前者可以從資料算出來，後者需要標註。

同時我不會一頁一頁猜 ID。先看看工具有沒有「列舉」能力。

list_screensread工具描述
Enumerate screens with their layout archetype and count them
by archetype. Default unique:true keeps one row per (structure
hash + headline), so 512 duplicated screens collapse to 291.

專案規範也寫了同一件事：「有多少」一律先 list_screens，不要自己遍歷資料庫。

2 · 選工具

agent

任務問的是「哪些、多少」，這是列舉問題，不是「這一頁長什麼樣」。

如果選錯後果
screen_sheet一次只回一頁，要先知道 ID；拿它回答「有多少」只能靠猜
直接查資料庫把版面判斷搬進模型，結果不可重跑

所以選 list_screens：它一次回全部，而且數字是 server 算的。

3 · 第一次查詢

agent
tools/calllist_screensok{}
total          291
page           172
overlay-panel   87
overlay         32

回傳裡還有一筆明細，長這樣：

rowscreens[0]
{ "id": "1:102753", "name": "Dialog-page", "page": "Withdraw",
  "archetype": "overlay-panel", "nodes": 51,
  "family": "d4319d6dc784" }

4 · 解讀

agent

三個數字放在一起，答案的形狀就出來了：

87 個有面板的彈窗 · 32 個只有遮罩、沒有面板 · 合計 119

291 是「不同畫面」的數量（結構 + 標題去重），不是節點數，也不是原始畫面總數（512 張含複本）。

如果你說的是「設計師分類為 dialog」，目前只有 42 個畫面有標註，其餘無法判定——我不會用結構答案冒充語意答案。

5 · 追問

你
為什麼 1:102753 算彈窗？它裡面有文字啊。
agent

有文字，但文字在面板那一層，不在遮罩。判斷的是遮罩層。

它在資料庫裡的三個直接子節點：

child_index型別名稱尺寸子樹文字節點
0SLOTpage-slot390 × 8440
1INSTANCEmask390 × 8440
2SLOTDialog-Slot280 × 2767
條件一
這一層與畫布同尺寸mask：390 × 844，容差 ±3px
條件二
這一層的子樹沒有文字mask 是 0；面板的 7 個不算在內
條件三
緊鄰上方是更小的面板280 × 276，面積小於畫布一半

三個同時成立 → overlay-panel。

為什麼要檢查文字？如果一個整頁大小的圖層上面浮著小元件（例如 Toast），沒有這條檢查就會被誤判成彈窗。遮罩是純色／半透明矩形，不該有文字。

對照：1:102743（Withdraw 頁）的子節點是狀態列 47、導覽列 44、內容 492、Home indicator 34、Toast 96——沒有任何一個是 844，所以是 page。

6 · 家族

agent

要確認「這頁有幾個複本」，再查一次：

tools/callscreen_familyok{ id: "1:102753" }
hash     d4319d6dc784
members  1:103166, 1:102908, 1:102765, 1:102761 …
         每個都是 51 個節點、Dialog-page

這就是「相似」在離散資料上的樣子：不是像素接近，是同一組結構關係。同一個彈窗被複製 20 次，在資料裡就是同一個 hash 出現 20 次。

hash 的算法是 md5(型別 + 依序的子節點 hash)，子樹被壓成 32 字元。所以比對結構不必比 16 萬個節點，只比 hash。

7 · 答案

agent
這份檔案有 291 個不同畫面。結構上的彈窗有 119 個：87 個帶面板、32 個只有遮罩。
如果你指的是「設計師分類為 dialog」，目前只有 42 個畫面有標註，其餘無法判定。
例：1:102753 是帶面板的彈窗（51 個節點，家族 d4319d6dc784）。

要清單就再往下鑽（list_screens 帶 archetype）；要確認就開複審看板，設計師勾選後把判斷寫回 labels。

整個流程裡，我只做了三件事：讀懂任務、選對工具、把數字翻譯成答案。計數、分群、判斷，全部在資料層完成。

你
那什麼情況會不準？
agent
情況結果
遮罩被畫進元件內部，沒有獨立圖層可能判成 page，需要人工複審
全螢幕但沒有遮罩（例如引導頁）落在 page，這是對的
畫布尺寸不是 390×844要改掃描尺寸，否則一頁都掃不到

所以我剛才說的是「結構上的彈窗有 87 個」，不是「彈窗有 87 個」。
