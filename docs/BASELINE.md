## 2. 方法

沿用現有 Tier 2 風格分類器：

- 特徵：主字體家族、token 比率、palette Jaccard、圓角 Jaccard
- 權重：字體 0.4 / token 0.35 / palette 0.1 / 圓角 0.15
- 判定：分數差距 < 0.1 → unknown（放棄）
- 驗證：leave-one-out（每個樣本從自己的類別統計中扣除）

## 2.1 指標定義

| 指標 | 意思 |
|---|---|
| 嚴格正確率 | 只有「預測 = 正確」才算對；答 unknown 也算錯。 |
| 強制 top1 | 不准放棄，永遠取最高分的那一類；代表「就算硬猜，能猜對多少」。 |
| 放棄率 | 模型主動回 unknown 的比例；太高代表它對這批資料沒有把握。 |
| top3 | 正確類有沒有進前三名；用來判斷「排序」是否還有救。 |

這三個數字不是說標註錯了，而是說**現有風格分類器不足以處理 30 類**：它幾乎都選擇放棄，硬猜也只有三分之一會中。

## 3. 結果

| 任務 | 樣本 | 嚴格 accuracy | 強制 top1 | 放棄率 | top3 |

| 世代（old/new） | 1,345 | 0/1,345 = **0%** | 375/1,345 = **28%** | **100%** | 100% |

### 對照：顏色＋結構模型（先前驗證）

- 世代任務（只用顏色）：人工標註 163 筆上 LOO = **99%**
- 只用結構：93%；只用顏色：99%（權重 3）

結論：**現有風格分類器不足以支撐 30 類與世代任務**；世代用顏色指紋即可（99%），分類需要結構與頁面脈絡。

## 4.1 設計決策（2026-11-23）

1. **世代（老UI/新UI）只用顏色指紋**：顏色單獨在人工標註上已達 99%，不需要再綁字體/token/圓角規則。
2. **圓角不是穩定特徵**：同一個 UI 體系的容器本來就會有不同圓角，不能寫死「某個圓角 = 某個世代」。
3. **風格特徵只用來描述，不用來當硬分類規則**：font/token/palette/radius 保留在 screen_sheet 與 style_profile，但不作為分類器的硬條件。
4. **不同語意允許存在**：同結構、同標題可以有不同標籤（頁面脈絡不同），461 筆衝突不是資料錯誤；建模時要保留上下文，而不是強制合併。

## 5. 對 Part 2 的意義



1. **Stage 5**：剝洋蔥正規化 + Tier 1.5 鬆弛指紋；可合併的命名收斂，語意不同的保留。
2. **世代**：顏色指紋必須進模型，純風格特徵不可用。
3. **分類**：需要階層（大類 → 小類）與頁面脈絡，不能只用全域風格相似度。
4. **unknown 門檻**：目前 margin 0.1 造成 97% 放棄；Part 2 要重新校準，而不是直接降低門檻。
5. **衝突處理**：461 筆同結構不同標籤是允許的（頁面脈絡不同）；建模保留上下文，不強制合併。
